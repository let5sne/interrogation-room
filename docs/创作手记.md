# 创作手记 ·《审讯室 / 谎言侦探》

> 参赛：AI+∞ 开发者创作大赛 第三期「AI 造游戏」· 方向：故事与 AI NPC
> 玩法一句话：你是侦探，对面是一个会说谎、会记仇、记得你说过每句话的 AI 嫌疑人。

---

## 一、创意与玩法

**灵感**：市面上多数「AI 游戏」只是用 AI 生成几张图、几段文案。我想做一个 **AI 在运行时真正"活着"** 的游戏——一个你无法用固定剧本通关的对手。

**核心设定**：一桩古董商命案，你是侦探，对面坐着嫌疑人林晚。她藏着秘密（她是凶手，且挪用了公司资金），会撒谎、回避、反咬，但**记得你说过的每句话、出示过的每个证据**。

**核心循环**：
1. 自由提问 / 施压 / 观察微表情
2. 出示证据 → 若与她的说法冲突，触发「矛盾！」，镇定暴跌
3. 镇定值驱动她的语气（从容 → 不耐烦 → 慌乱 → 濒临崩溃 → 崩溃招供）
4. 无证据乱施压 3 次 → 她要求律师，审讯终止（失败）
5. 提交「凶手 + 手法 + 动机」→ 破案 / 放跑真凶 + 真相揭晓

**AI 原生机制（本作最关键的设计）**：
- **真相档案（Ground Truth）**：服务端持有一份结构化"真相"，绝不下发前端（防作弊）。
- **谎言一致性引擎**：LLM 被约束"必须维持与真相一致的谎言"，不能自相矛盾。
- **跨回合记忆**：每回合把"已确立事实 + 已揭穿矛盾 + 对话历史"注入提示词。
- **矛盾检测 + 镇定状态机**：出示证据命中矛盾 → 镇定大跌；镇定过低 → 破防招供。

---

## 二、创作过程

- **设计**：先用 AI 头脑风暴 → 确定「AI 审讯」方向 → 写设计文档（真相档案/谎言引擎/镇定状态机/数据流）→ 拆成 18 个可独立测试的任务。
- **实现**：严格按 TDD 逐任务推进：先写失败测试 → 实现 → 跑通 → 提交，共 21 次提交。
- **验证**：27 个单元/集成测试全绿；Docker 镜像构建并容器内跑通；用 Playwright 截图核对了界面与完整玩法流程。

---

## 三、工具应用与体验

- **AI 辅助编码**：用 AI 完成设计、编码、测试、重构的大部分工作；我负责定方向、评审代码、把控质量。
- **运行时 AI**：游戏内的嫌疑人由 ModelScope 的 OpenAI 兼容推理接口实时驱动（Qwen / DeepSeek 系列），Key 走环境变量。
- **体验亮点**：AI 的对手感非常真实——它会狡辩、会记仇、会因为你的证据突然慌乱，这种"不可预测但合逻辑"的体验是静态脚本做不出来的。

---

## 四、问题解决（踩坑）

1. **AI 圆谎不一致**：早期模型会自相矛盾。解法：服务端真相档案 + 每回合强制注入"已确立事实" + "不得违背"约束，把"自由发挥"关进"逻辑一致"的笼子里。
2. **响应延迟**：流式输出 + 精简提示词 + 加载态，保证对话"打字机"般自然。
3. **防作弊**：真相、矛盾判定、胜负结算全部在服务端，前端只拿证据的名称和描述，看不到答案。
4. **连接泄漏**：SQLite 连接未关闭导致句柄泄漏，改用 `contextlib.closing` 显式关闭并验证 0 泄漏。
5. **部署**：Docker 化 + 魔搭创空间一键部署，Key 走密钥变量。

## 六、总结

这个作品想证明一件事：**AI 不只是"生成素材"的工具，它可以是游戏机制本身**。当对手会记忆、会即兴、会因你而变，游戏就从"通关"变成了"博弈"。
